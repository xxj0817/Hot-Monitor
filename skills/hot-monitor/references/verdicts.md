# 判定语义与汇报话术

本技能的判定分两层，**不要混为一谈**：

1. **相关性（related / coverage）**：这条内容是否真的在讲被监控的关键词。由本地闸门保证（字面/等价叫法命中），`coverage` 表示关键词实体词被覆盖的比例。
2. **真伪（verdict / authentic）**：这条内容可不可信。只有配置了 AI Key 才有结论；否则一律 `unverified`。

## verdict 语义表

| verdict | 触发条件 | 含义 | 推荐话术 |
|---|---|---|---|
| `authentic` | AI 判定真实，或官方来源 + 多源印证 | 已确认的新动态 | "已确认：xxx（来源：链接）" |
| `unverified` | 未配置 Key；或 AI 无法确认 | 有讨论，但未证实 | "有讨论称 xxx，尚未证实" |
| `fake` | AI 判定为谣言/营销号/旧闻炒作 | 疑似不实内容 | "疑似不实信息，不建议作为素材；如需使用请先核实" |
| `unrelated` | 未通过关键词闸门 | 与关键词无关 | "与 X 无关（未命中关键词）" |
| `demo` | `--mock` 演示数据 | 演示样例 | "演示数据，仅用于验证链路" |

## 汇报模板

**关键词动态（scan / signals）**

```
【关键词】Claude Sonnet 4.6　【时间窗】近 7 天　【模式】AI 判定
1. <标题>（来源 / 时间 / 覆盖度 100% / 3 源印证）
   依据：「<evidence>」
   判定：<reason>
   链接：<url>
...
过滤：已丢弃 N 条与关键词无关的内容（no-term=x, low-coverage=y）
```

**领域热点（trend）**

```
【领域】AI 编程　【时间窗】近 3 天
1. [S] <标题>（热度 78，3 源印证，2 个检索词命中）链接
...
```

**单条核验（judge）**

```
结论：<verdict 话术>；相关性覆盖度 xx%
依据：「<evidence>」→ <why>
理由：<reason>
```

## 硬性约束

- 每条结论必须带 `url`；没有链接就不要输出该条。
- `coverage < 1`：说明只命中了部分实体词（如只提 "Sonnet" 未提版本号），汇报时加"部分提及"的限定。
- `mode: "no-key"`：必须声明"仅完成相关性判定，真伪未核验"，并给出配置 Key 的建议。
- `engineCount = 1`：单一信源，标注"单一来源，待交叉印证"。
- **绝不**把 `unverified` 说成"已确认"，**绝不**把 `fake` 当事实引用，**绝不**编造未见过的标题或链接。
- 采集失败要如实说明（例如"360 资讯被风控，本次只有必应结果"），不要用记忆里的旧消息补位。
- 引用内容时给出来源链接并做简短转述；不要整段复制他人正文。
